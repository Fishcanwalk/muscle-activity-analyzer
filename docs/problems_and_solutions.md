รวมปัญหาที่เจอระหว่างพัฒนาระบบ Cyberpump ทั้งฝั่งฮาร์ดแวร์ firmware เว็บ และการ deploy

[`troubleshooting_nginx_reverse_proxy.md`](troubleshooting_nginx_reverse_proxy.md)

## Deploy และเซิร์ฟเวอร์

### 1. Docker build ล้มเพราะ `poetry.lock` ไม่ตรง ✅

**อาการ:** build image backend บน server ไม่ผ่าน แจ้งว่า `pyproject.toml changed significantly since poetry.lock was last generated`
และในเครื่องรัน `poetry` ไม่ได้ (`poetry: command not found`)

**สาเหตุ:** มีการแก้ dependency ใน `pyproject.toml` แต่ไม่ได้สร้าง `poetry.lock` ใหม่

**วิธีแก้:** สร้าง lock ใหม่ด้วย Poetry 2 ผ่าน `uvx` โดยไม่ต้องติดตั้ง Poetry ถาวร แล้ว commit ไฟล์ lock

```bash
cd backend && uvx --from 'poetry>=2' poetry lock
```

### 2. Backend container ต่อ Docker network เก่า / login ขึ้น ECONNREFUSED ✅

**อาการ:** login แล้ว frontend log ขึ้น `connect ECONNREFUSED 127.0.0.1:9011` และรัน backend ใหม่แล้วชนพอร์ต
(`Address already in use`)

**สาเหตุ:**
- container backend ยังผูกอยู่กับ Docker network เดิมที่ถูกสร้างใหม่ไปแล้ว frontend จึงหาไม่เจอ
- ในเครื่อง dev พอร์ต 9000 ถูกโปรเจกต์อื่นใช้อยู่ backend ของโปรเจกต์นี้จึงต้องรันที่ 9011
  (`BACKEND_API_URL` ใน `frontend/.env`) ถ้าไม่ได้เปิด backend ไว้ที่ 9011 จะ login ไม่ได้

**วิธีแก้:** สร้าง container ใหม่ให้ต่อ network ปัจจุบัน (`docker compose up -d --force-recreate backend`)
และตรวจว่า backend รันอยู่ที่พอร์ตเดียวกับ `BACKEND_API_URL`

### 3. SSE หลุดบน production (`ERR_INCOMPLETE_CHUNKED_ENCODING`) ✅

**อาการ:** บน `https://cyberpump.online` console ขึ้น `api/telemetry/stream net::ERR_INCOMPLETE_CHUNKED_ENCODING`
ข้อมูลสดหยุดเป็นระยะ แต่ในเครื่อง dev ไม่เป็น

**สาเหตุ:** nginx ตัดการเชื่อมต่อที่เงียบเกิน 60 วินาที (`proxy_read_timeout`) ซึ่ง SSE จะเงียบทุกครั้งที่บอร์ดไม่ได้ส่งข้อมูล
และ nginx ยัง buffer response ไว้ด้วย

**วิธีแก้:** ส่ง comment `: ping` ทุก 15 วินาที และเพิ่ม header `X-Accel-Buffering: no` กับ
`Cache-Control: no-cache, no-transform` ใน [`stream/+server.ts`](../frontend/src/routes/api/telemetry/stream/+server.ts)
ทดสอบหลัง nginx ใน Docker แล้ว: โค้ดเดิมถูกตัดที่ 20 วินาที โค้ดใหม่อยู่ได้เกิน 45 วินาที
WebSocket `/ws/emg` ใช้วิธีเดียวกันคือ ping ทุก 15 วินาที

## Firmware ESP32

### 4. Compile firmware ไม่ผ่าน `WiFi.h: No such file` 🔧

**สาเหตุ:** Arduino IDE ยังไม่ได้ติดตั้ง ESP32 core หรือเลือกบอร์ดผิด (เลือกเป็น Uno)

**วิธีแก้:** ติดตั้ง **esp32 by Espressif** (ใช้เวอร์ชัน 3.x) ผ่าน Boards Manager แล้วเลือกบอร์ด `ESP32 Dev Module`
firmware ใส่ `#error` ไว้ ถ้าใช้ core เวอร์ชันต่ำกว่า 3 จะแจ้งทันที library ที่ต้องติดตั้งเพิ่มคือ
**WebSockets** (by Markus Sattler), SparkFun MAX3010x, Adafruit MLX90614 และ LiquidCrystal I2C

### 5. Compile ไม่ผ่าน `checkForBeat was not declared in this scope` ✅

**สาเหตุ:** commit `9deb4fe` ลบ `#include "heartRate.h"` ออก แต่โค้ดวัดชีพจรยังเรียก `checkForBeat()` อยู่

**วิธีแก้:** ใส่ `#include "heartRate.h"` กลับใน [`esp32_workout_firmware.ino`](../test-sensor/arduino/esp32_workout_firmware/esp32_workout_firmware.ino)

### 6. กดปุ่มค้างแล้วปล่อย นับเป็นอีกเซต ✅

**อาการ:** กดปุ่ม A ค้างไว้สักพักแล้วปล่อย ระบบนับเป็นการกดอีกครั้ง เริ่มหรือจบเซตเพิ่มเอง

**สาเหตุ:** หน้าสัมผัสปุ่มเด้ง (bounce) ตอนปล่อย ทำให้เกิดขอบขาลงซ้ำ debounce ใน ISR อย่างเดียวกันไม่ได้
ถ้าเด้งหลังผ่านไปเกิน 250 ms

**วิธีแก้:** ใน `controlTask` รอ 30 ms ให้หน้าสัมผัสนิ่ง แล้วอ่านขาซ้ำว่ายังกดอยู่จริง และรับการกดได้ครั้งเดียวต่อการกดหนึ่งรอบ
(ต้องปล่อยปุ่มก่อนถึงจะนับครั้งถัดไป)

### 7. Buzzer ไม่ดัง ✅

**อาการ:** ต่อ buzzer ที่ GPIO 25 แล้วไม่มีเสียง

**สาเหตุ:**
- buzzer เป็นแบบ **active** (มีวงจรกำเนิดเสียงในตัว แค่จ่ายไฟก็ดัง) แต่โค้ดเคยสั่งด้วย `tone()` ซึ่งเป็น PWM สำหรับ passive buzzer ทำให้ไม่มีเสียง
- เงื่อนไขเตือนเดิมใช้ค่า ADC ตายตัว ไม่ตรงกับค่า FSR ของแต่ละคน

**วิธีแก้:**
- สั่งด้วย `digitalWrite(HIGH/LOW)`
- เปลี่ยนเงื่อนไขเป็น % ของช่วง FSR ที่ calibrate ไว้ (เซิร์ฟเวอร์ส่ง `fsrZero`/`fsrMax` กลับมาในคำตอบของ POST)
  ดังเมื่อแรงกำตกเหลือต่ำกว่า 60% ของระดับที่บีบอยู่นานเกิน 200 ms หรือแรงกำไม่นิ่ง (stability < 70%) นานเกิน 3 วินาที
- เพิ่มปุ่ม "ทดสอบ buzzer" ในหน้า Calibration ไว้เช็คการต่อสาย

## เซนเซอร์และฮาร์ดแวร์

### 8. EMG ตอนพักสูง (~2000–3300 µV) ตอนเกร็งกลับได้ค่าต่ำ 🔧

**อาการ:** ก่อนเกร็งค่า EMG ค้างที่ประมาณ 2112 µV แล้วต่อมาค้างที่ 3300 µV พอเกร็งค่ากลับลดลง
ค่าที่ calibrate ได้จึงเป็น "จุดพักสูง แรงสูงสุดต่ำ" (0–8 µV)

**สาเหตุ:** 3300 คือเพดานของสเกลพอดี (ADC 4095 → 3300 mV) แปลว่าขา SIG ชนเพดาน ADC ตลอดตอนพัก
ไม่ใช่สัญญาณกล้ามเนื้อจริง เกิดจากฮาร์ดแวร์ เช่น สาย SIG หลวมจนขาลอย, อิเล็กโทรดอ้างอิง (REF) แนบผิวไม่ดี,
ตั้ง gain บนโมดูลสูงเกิน หรือต่อผิดไปที่ขา RAW

**วิธีแก้:**
- ไล่เช็คอิเล็กโทรดทั้ง 3 จุด สาย SIG เข้าขา A0 และลด gain บนโมดูล
- ตรวจค่าดิบด้วย [`02_semg_adc_test.ino`](../test-sensor/arduino/02_semg_adc_test/02_semg_adc_test.ino) บน Uno โดยตรง
- ฝั่งซอฟต์แวร์เพิ่มตัวกันที่หน้า Calibration: ไม่รับค่า MVC ที่ต่ำกว่า 50 µV (`MIN_EMG_MVC_UV`) เพื่อไม่ให้ calibrate ด้วยค่าที่ใช้ไม่ได้

### 9. Calibrate EMG ใหม่แล้วค่าไปบวกกับค่าเดิม ✅

**อาการ:** กด "วัดใหม่" แล้วค่าจุดพักหรือแรงสูงสุดกลายเป็นค่าใหม่บวกค่าที่ใช้อยู่

**สาเหตุ:** ค่าสดที่ใช้ calibrate เป็นค่าที่ลบ baseline ปัจจุบันไปแล้ว พอวัดซ้ำจึงลบซ้อน/บวกซ้อน

**วิธีแก้:** เซิร์ฟเวอร์ส่ง `emg.level` เป็นค่าเฉลี่ยดิบที่ยังไม่ลบ baseline หน้า Calibration ใช้ค่านี้วัดเสมอ วัดกี่ครั้งก็ได้ค่าเดิม

### 10. ค่า MVC ในกราฟพุ่งถึง 995% 🔧

**อาการ:** กราฟ EMG แสดงแรงสูงสุด 995% MVC

**สาเหตุ:** ไม่ใช่บั๊กการคำนวณ ค่า MVC ที่ calibrate ไว้ต่ำกว่าแรงจริงมาก (เช่น 50 µV แต่ยกจริงได้ 500 µV → 1000%)
ตัวเลขแสดงถูกจำกัดที่ 999% จึงเห็นเป็น 995

**วิธีแก้:** ตอน calibrate MVC ต้องเกร็งเต็มที่จริงๆ ไม่ใช่แค่ผ่านเกณฑ์ขั้นต่ำ

### 11. FSR วัดได้สูงสุดแค่ประมาณ 5 kg ✅

**สาเหตุ:** โค้ดเดิมแปลง ADC เป็นนิวตันด้วยค่าเต็มสเกลตายตัว 50 N ทุกคนจึงติดเพดานเท่ากัน
และ FSR เปล่าๆ ให้ค่านิวตันจริงไม่ได้ถ้าไม่มีน้ำหนักอ้างอิงมาสอบเทียบ

**วิธีแก้:** เปลี่ยนเป็น **% ของแรงบีบสูงสุดของผู้ใช้เอง** จากค่า calibrate `fsrZero` (ไม่บีบ) และ `fsrMax` (บีบสุด)
$$Grip\% = \frac{raw - fsrZero}{fsrMax - fsrZero} \times 100$$

### 12. ทดสอบความพร้อมได้ ~100% ทุกครั้ง ✅

**สาเหตุ:** ทดสอบแรงบีบเทียบกับ `fsrMax` ของ session เดียวกันที่เพิ่งวัดไป ผลจึงใกล้ 100% เสมอ ประเมินความล้าไม่ได้

**วิธีแก้:** เพิ่ม endpoint `POST /v1/readiness/grip` เก็บผลทดสอบทุกครั้ง (collection `grip_tests`)
แล้วเทียบกับค่ามัธยฐานของ 5 ครั้งก่อนหน้าของผู้ใช้คนนั้น ครั้งแรกบันทึกเป็นค่าอ้างอิง

### 13. MPU-6050 ความเร็วเพี้ยน / มุมเทียบกันไม่ได้ ✅

**อาการ:**
- ค่าจาก MPU ดูไม่มีประโยชน์ ความเร็วลอยขึ้นเองประมาณ 4 m/s ตอนวางนิ่ง
- ติดเซนเซอร์แต่ละครั้งมุมไม่เท่ากัน ค่ามุมเอียงเทียบข้าม session ไม่ได้

**สาเหตุ:** การอินทิเกรตความเร่งสะสม error ทุกรอบ (velocity drift) และค่าแรงโน้มถ่วง 9.8 ที่ใช้ลบออกไม่ตรงกับเซนเซอร์จริง

**วิธีแก้:**
- หาทิศ "ขึ้น" ใหม่ทุกครั้งด้วยการหมุนเวกเตอร์แรงโน้มถ่วงตามไจโร (complementary filter 0.98) จึงไม่ขึ้นกับมุมติดตั้ง
- เรียนรู้ขนาดแรงโน้มถ่วงจริงของเซนเซอร์ระหว่างที่นิ่ง (`gravityRefMss`)
- คูณความเร็วด้วย 0.998 ทุกรอบ และรีเซ็ตเป็น 0 เมื่อนิ่งจริงต่อเนื่อง 150 ms
- เอา pitch/roll และค่าดิบรายแกนออก ส่งเฉพาะ `velocity` กับ `peakVelocity` (ความเร็วสูงสุดในแต่ละรอบส่ง)

### 14. ชีพจร "สูงสุดขณะยก" เป็น 159 BPM ทุกการฝึก ✅

**สาเหตุ:**
- ค่าสูงสุดไม่เคยถูกรีเซ็ต จำค่าเดียวไว้ตลอดที่เปิดหน้าเว็บ
- MAX30102 ให้ค่าหลอกชั่วขณะเมื่อนิ้วขยับระหว่างยก และ firmware เก็บจังหวะเก่าไว้ในค่าเฉลี่ยหลังยกนิ้วออก

**วิธีแก้:**
- เว็บ ([`telemetry.svelte.ts`](../frontend/src/lib/workout/telemetry.svelte.ts)): รีเซ็ตทุกครั้งที่เริ่มเซต นับเฉพาะตอนกำลังยก
  และต้องค้างอย่างน้อย 3 วินาทีถึงนับเป็นค่าสูงสุด
- firmware: ล้างจังหวะเก่าเมื่อไม่มีนิ้ว และรอครบ 4 จังหวะใหม่ก่อนรายงาน

### 15. MLX90614 อ่านอุณหภูมิไม่ได้ (`skinTemp=0`, `nan`) 🔧

**อาการ:**
- ใน log `skinTemp=0.0C` ตลอด
- เพื่อนสังเกตว่าเริ่มเป็นหลังตั้งให้ส่งข้อมูลเร็วกว่า 250 ms
- I2C scanner เจอ LCD, MAX30102, MPU แต่ไม่เจอ `0x5A` และเจอ address แปลก `0x00`, `0x02`
- `mlx.begin()` ผ่านบางครั้งแต่อ่านค่าได้ `nan`

**สาเหตุ:**
- **ไม่ใช่ความเร็วในการส่ง:** firmware อ่าน MLX ทุก 250 ms ใน `sensorTask` แยกจาก `networkTask` ที่ส่งข้อมูล
  และสเก็ตช์ทดสอบที่ไม่มี WiFi เลยก็อ่านไม่ได้เหมือนกัน
- **ต้นเหตุจริงคือจุดต่อของ MLX90614:** เซนเซอร์ตอบ address ได้บ้างไม่ได้บ้าง และส่งข้อมูลกลับไม่ได้
  ขณะที่ตัวอื่นบนบัสเดียวกันใช้ได้ปกติ สุดท้ายต่อสายใหม่แล้วกลับมาใช้ได้

**วิธีแก้:**
- เช็คสาย VIN, GND, SDA, SCL ของ MLX ให้แน่น และตัดไฟทั้งบอร์ดแล้วเสียบใหม่
  (กด EN/RST รีเซ็ตแค่ ESP32 เซนเซอร์ยังมีไฟอยู่)
- ถ้าต่อหลายโมดูลบนบัสเดียวกัน ระวังโมดูล MAX30102 บางรุ่นที่ดึง pull-up ไป 1.8V ทำให้ MLX อ่านพลาด
- เครื่องมือตรวจ:
  - [`01_i2c_scanner`](../test-sensor/arduino/01_i2c_scanner/01_i2c_scanner.ino) ดู address ที่ตอบ
  - [`06_mlx90614_test`](../test-sensor/arduino/06_mlx90614_test/06_mlx90614_test.ino) อ่าน MLX อย่างเดียว
  - [`10_mlx90614_address_fix`](../test-sensor/arduino/10_mlx90614_address_fix/10_mlx90614_address_fix.ino)
    อ่าน address ใน EEPROM ของ MLX และตั้งกลับเป็น 0x5A ได้ถ้าถูกเปลี่ยน

### 16. สเก็ตช์ทดสอบ MLX90614 "ค้าง" หลัง upload ✅

**สาเหตุ:** `06_mlx90614_test` ตั้งใจหยุดด้วย `while (1)` เมื่อหาเซนเซอร์ไม่เจอ ข้อความ error พิมพ์ครั้งเดียวตอนบูต
ถ้าเปิด Serial Monitor ทีหลังจะไม่เห็นข้อความ ดูเหมือนบอร์ดแฮงก์

**วิธีแก้:** เปลี่ยนเป็นลองเชื่อมต่อใหม่ทุก 1 วินาทีพร้อมพิมพ์สถานะ ใช้ขยับสายแล้วดูผลสดได้
สเก็ตช์ `10_mlx90614_address_fix` ก็พิมพ์คำแนะนำซ้ำทุก 5 วินาทีและรับคำสั่ง `r` เพื่อตรวจใหม่

## เครือข่าย

### 17. เว็บเชื่อมต่อบอร์ดได้บ้างไม่ได้บ้าง (IP เปลี่ยน) 🔧

**อาการ:** บางวันข้อมูลจากบอร์ดเข้าเว็บ บางวันไม่เข้า เซนเซอร์ทุกตัวหายพร้อมกัน

**สาเหตุ:** firmware ระบุ IP ของโน้ตบุ๊กที่รันเว็บไว้ตายตัว (`serverUrl`) พอโน้ตบุ๊กเปลี่ยน WiFi หรือได้ IP ใหม่
บอร์ดก็ส่งไป IP ที่ไม่มีใครรับ และบอร์ดกับโน้ตบุ๊กต้องอยู่ WiFi วงเดียวกันด้วย

**วิธีแก้:** ส่งตรงไปที่ server จริงแทน (`SERVER_HOST = "cyberpump.online"`) ใช้ WiFi ไหนก็ได้ที่ออกอินเทอร์เน็ต
ถ้าจะใช้กับเครื่อง dev ต้องแก้ `SERVER_HOST` ให้ตรง IP ปัจจุบัน (ดูด้วย `hostname -I`)
IP กับพอร์ตรวมไว้ที่ `SERVER_HOST`/`SERVER_PORT` จุดเดียว

### 18. เว็บเชื่อมต่อบอร์ดหลุดเป็นช่วงๆ บน WiFi PSU888 🔧

**อาการ:** เซนเซอร์ทุกตัวใช้ได้แล้ว แต่บนเว็บบางช่วงขึ้นว่าเชื่อมต่ออุปกรณ์ไม่ได้

**สาเหตุ:** WiFi PSU888 ไม่เสถียร วัดจากเครื่องที่ต่อ WiFi เดียวกัน:

| ทดสอบ | ผล |
|---|---|
| สถานะบอร์ดบน production ทุกวินาที (90 วินาที) | POST และ WebSocket หยุด**พร้อมกัน** ช่วงละ 3–6 วินาที และมีช่วงหายเกิน 25 วินาที |
| ping router ของ WiFi | packet loss 5% |
| ping cyberpump.online | packet loss 15% |
| curl google.com | timeout และ DNS หาชื่อไม่เจอเป็นช่วงๆ |

สองช่องทางหยุดพร้อมกันแปลว่าเครือข่ายขาด ไม่ใช่บั๊ก และบอร์ดต้องหา IP ของ `cyberpump.online` ใหม่ทุกครั้งที่ต่อใหม่
ถ้า DNS ล่มตอนนั้นจะหลุดนานขึ้น นอกจากนี้ POST ผ่านอินเทอร์เน็ตใช้เวลา 220–290 ms อัตราส่งจริงจึงประมาณ 4 ครั้งต่อวินาที

**วิธีแก้:** ใช้เครือข่ายที่เสถียร เช่น hotspot มือถือหรือ router ของตัวเองวางใกล้บอร์ด
ถ้าต้องใช้ PSU888 ให้ดูค่า `RSSI=` ใน Serial Monitor (ต่ำกว่าประมาณ -75 คือสัญญาณอ่อน)

## สถาปัตยกรรมและฟีเจอร์

### 19. ค่า EMG บนเว็บไม่เรียลไทม์ ✅

**อาการ:** กราฟ EMG อัปเดตเป็นก้อนทุก 250 ms อาจารย์แนะนำให้ใช้ WebSocket

**สาเหตุ:** EMG ถูกรวมไปกับ HTTP POST ของเซนเซอร์อื่น ต้องเปิด request ใหม่และรอคำตอบทุกครั้ง

**วิธีแก้:** ย้าย EMG ไปใช้ WebSocket `/ws/emg` ทั้งเส้นทาง บอร์ดส่งทุก 20 ms ผ่าน task ใหม่ `EmgStreamTask`
เซนเซอร์อื่นยังใช้ POST ทุก 100 ms + SSE รายละเอียดใน [`emg_websocket_migration.md`](emg_websocket_migration.md)

### 20. นับ rep จากกล้องกับ EMG ปนกัน / กล้องหนักเครื่อง ✅

**สาเหตุ:** เดิมใช้ MediaPipe/OpenCV จับมุมข้อศอกเพื่อนับ rep และตรวจการโกงควบคู่กับ EMG ผลขัดกันเองและใช้ทรัพยากรเครื่องมาก

**วิธีแก้:**
- นับ rep และตัดสินการโกงจาก EMG อย่างเดียว rep ที่ค่าสูงสุดไม่ถึงเกณฑ์ "ออกแรงจริง" (45%) นับเป็นโกง
- กล้องเหลือเป็นภาพให้ดูฟอร์มเฉยๆ ไม่ประมวลผล และเอา MediaPipe, OpenCV และ ROM ออก
- ปุ่มบนบอร์ดเป็นทางเดียวที่ใช้เริ่ม/จบเซต (A) และจบการออกกำลังกาย (B)

### 21. วันที่ในปริมาณงานรายสัปดาห์ผิดวัน ✅

**อาการ:** ฝึกวันที่ 27 ก.ย. แต่แสดงเป็น 21 ก.ย.

**สาเหตุ:**
- ป้ายแสดงวันจันทร์ต้นสัปดาห์ ไม่ใช่วันที่ฝึก
- เซิร์ฟเวอร์คิดวันแบบ UTC และ MongoDB คืนเวลาแบบไม่มี timezone เบราว์เซอร์ในไทยจึงอ่านเป็นเวลาไทย
  การฝึกช่วง 00:00–07:00 จะถูกนับเป็นวันก่อนหน้า

**วิธีแก้:**
- แสดงเป็นช่วงสัปดาห์ เช่น "21–27 ก.ย." และคิดวันทั้งหมดเป็นเวลาไทย (`Asia/Bangkok`)
- ตั้ง Motor client เป็น `tz_aware=True` ([`db.py`](../backend/app/db.py)) API จะส่งเวลาพร้อม `Z`

### 22. `session_id` เป็น null และมีเซต 0 ครั้งเต็ม database ✅

**อาการ:** ใน `session_results` มีเซตจำนวนมากที่ `totalReps: 0` และ `session_id: null`

**สาเหตุ:** เซตจากการทดสอบปุ่มและทดสอบระบบถูกบันทึกทั้งที่ไม่มีครั้งที่นับได้ บางเซตบันทึกโดยไม่ผ่าน flow ปกติจึงไม่มี `session_id`

**วิธีแก้:**
- เว็บไม่ส่งเซตที่ไม่มีครั้ง ถ้าทั้ง session ไม่มีเซตที่นับได้จะไม่บันทึก session นั้น
- `POST /v1/sessions` ตอบ 422 ถ้า `totalReps < 1`
- สคริปต์ลบข้อมูลเก่า [`cleanup_empty_sets.py`](../backend/app/cleanup_empty_sets.py) (ค่าเริ่มต้นเป็น dry run):
  ```bash
  docker exec cyberpump-backend python -m app.cleanup_empty_sets          # ดูก่อน
  docker exec cyberpump-backend python -m app.cleanup_empty_sets --apply  # ลบจริง
  ```

### 23. เปิดดูค่าของ session เก่าไม่ได้ ✅

**วิธีแก้:** เพิ่มหน้า `/sessions/[id]` แต่ละแถวใน "ประวัติการฝึก" บน Dashboard กดเข้าไปดูได้
แสดงภาพรวม, ข้อมูลทุกเซตและทุก rep, และเทียบกับ session ก่อนหน้าพร้อมลิงก์ย้อนกลับไปดูทีละ session

### 24. หน้า Live Studio ไม่พอดีหน้าจอ ✅

**วิธีแก้:** จัด layout ให้กราฟ EMG, ค่าเซนเซอร์ และกล้องอยู่ในหน้าจอเดียวบนจอขนาด lg ขึ้นไป
กราฟปรับขนาดตามกรอบด้วย `ResizeObserver` และย้ายคำอธิบายเส้นเกณฑ์ไปไว้มุมขวาบน

## ยังไม่ได้แก้

### 25. "เวลาเกร็งนานสุด" (High-Tension TUT) เป็น 0 เสมอ ⚠️

**สาเหตุ:** ฟังก์ชัน `incrementTut()` ใน [`workout.svelte.ts`](../frontend/src/lib/workout/workout.svelte.ts) ไม่มีที่ไหนเรียกใช้
และถ้าเรียก ค่าเพิ่มครั้งละ 0.02 แล้วปัดทศนิยม 1 ตำแหน่ง ก็จะถูกปัดทิ้งเป็น 0 ทุกครั้ง

**แนวทางแก้:** นับเวลาที่สัญญาณ EMG อยู่เหนือเกณฑ์ "ออกแรงจริง" ระหว่างเซต (คำนวณจาก sample ที่มาทาง WebSocket)
แล้วบันทึกเป็นวินาที

### 26. ความเร็วทุก rep เป็น 0 m/s ในหน้าสรุปเซต ⚠️

**อาการ:** ตารางความเร็วแต่ละครั้งเป็น 0 m/s ทุกครั้ง "ครั้งที่กระตุ้นกล้ามเนื้อ" จึงเป็น 0 ไปด้วย

**สาเหตุที่เป็นไปได้:** ค่า MPU ช่วงนั้นเพี้ยน (log เห็น `MPU vel=26 m/s` ตอนวางนิ่ง) หรือค่า `peakVelocity`
ไม่มาถึงเบราว์เซอร์ในช่วงเวลาของ rep เพราะเครือข่ายขาดช่วง (ข้อ 18) ต้องตรวจแยก

### 27. สถานะ `device.connected` ไม่เคยกลับเป็น false ⚠️

**สาเหตุ:** เซิร์ฟเวอร์ตั้ง `connected: true` เมื่อได้รับข้อมูล แต่ไม่มีโค้ดตั้งกลับเป็น false เมื่อบอร์ดหายไป
หน้าเว็บจึงพึ่งเวลาที่เห็นข้อมูลล่าสุดของแต่ละเซนเซอร์ (เกิน 2.5 วินาทีขึ้น "สัญญาณขาด") แทน

**แนวทางแก้:** ให้ `device.connected` เป็น false เมื่อไม่มีข้อมูลเกินช่วงเวลาหนึ่ง
