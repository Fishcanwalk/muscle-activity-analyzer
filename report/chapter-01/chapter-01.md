# บทที่ 1 บทนำ

## 1.1 ที่มาและความสำคัญของปัญหา

การฝึกเวทโดยทั่วไปยังอาศัยการนับจำนวนครั้งและการสังเกตด้วยสายตาของผู้ฝึกหรือผู้ฝึกสอนเป็นหลัก ซึ่งบอกได้เพียงว่าออกแรงครบเซตหรือไม่ แต่ไม่สามารถบอกรายละเอียดที่ส่งผลต่อคุณภาพและความปลอดภัยของการฝึกได้ เช่น กล้ามเนื้อมัดที่ออกแรงจริงมีความเข้มข้นเพียงใด ท่าทางเริ่มเสียรูปหรือเริ่มล้าตั้งแต่ครั้งใด ความเร็วในการยกลดลงมากน้อยเพียงใดเมื่อเทียบกับครั้งแรกของเซต และร่างกายตอบสนองต่อภาระงานอย่างไรระหว่างออกกำลังกาย ข้อจำกัดเหล่านี้ทำให้การประเมินผลขึ้นอยู่กับประสบการณ์ของผู้สังเกตและมีความคลาดเคลื่อนสูง โดยเฉพาะเมื่อผู้ฝึกต้องประเมินตนเองโดยไม่มีผู้ฝึกสอนอยู่ด้วย

โครงงานนี้จึงพัฒนาระบบที่รวมข้อมูลจากกล้องและเซนเซอร์หลายชนิดเข้าด้วยกัน โดยแต่ละแหล่งข้อมูลตอบโจทย์คนละด้านของการฝึก ได้แก่ สัญญาณ sEMG จากกล้ามเนื้อบ่งบอกระดับการทำงานและความล้าของมัดกล้ามเนื้อที่วัด แรงกดจาก FSR สะท้อนความมั่นคงของการจับหรือของท่าทาง ข้อมูลจาก IMU (MPU6050/MPU6500) ใช้คำนวณระยะการเคลื่อนไหว (ROM) ความเร็วในการยก และการสูญเสียความเร็วระหว่างเซตซึ่งเป็นตัวชี้วัดความล้าที่ใช้ในการฝึกแบบ autoregulation ส่วนอัตราการเต้นหัวใจ ค่า SpO2 จาก MAX30102 และอุณหภูมิผิวจาก MLX90614 ใช้ติดตามภาระทางสรีรวิทยาระหว่างออกแรง และกล้องร่วมกับ MediaPipe/OpenCV ใช้ช่วยนับจำนวนครั้งและตรวจสอบความถูกต้องของท่าทางอีกชั้นหนึ่ง เมื่อรวมข้อมูลเหล่านี้เข้าด้วยกัน ผู้ฝึกจะเห็นข้อมูลประกอบการตัดสินใจระหว่างทำเซต เช่น ควรหยุดหรือลดน้ำหนักเมื่อความเร็วตกหรือท่าเริ่มเสียรูป และใช้ข้อมูลสรุปท้ายเซตหรือท้ายเซสชันประกอบการประเมินผลการฝึกย้อนหลัง

ความสำคัญของระบบอยู่ที่การรวมข้อมูลหลายแหล่งเข้าด้วยกันในเวลาจริง โดยแยกการอ่านสัญญาณที่ต้องใช้เวลาคงที่บนไมโครคอนโทรลเลอร์ (การอ่าน ADC และ I2C ที่ต้องทำอย่างต่อเนื่องไม่ให้ตกหล่น) ออกจากการแสดงผลและการจัดเก็บบนเว็บที่ต้องรองรับผู้ใช้หลายคนและการเชื่อมต่อที่อาจไม่เสถียร การแบ่งงานตามความสามารถของแต่ละอุปกรณ์เช่นนี้ทำให้แต่ละส่วนของระบบดูแล ทดสอบ และแก้ไขได้เป็นอิสระจากกันมากขึ้น อีกทั้งยังเป็นพื้นฐานที่สามารถต่อยอดไปสู่การวิเคราะห์การฝึกที่ละเอียดขึ้นในอนาคตได้

## 1.2 ปัญหาที่ต้องการแก้ไข

ปัญหาหลักคือข้อมูลจากเซนเซอร์แต่ละตัวมีรูปแบบและอัตราการอ่านต่างกัน ข้อมูล sEMG และ FSR ต้องอ่านถี่และต่อเนื่อง ขณะที่ข้อมูลอุณหภูมิเปลี่ยนช้ากว่า ส่วนข้อมูลจาก IMU และสัญญาณชีพต้องอ่านจากบัส I2C เดียวกัน นอกจากนี้ข้อมูลยังต้องเดินทางจาก Arduino Uno ไปยัง ESP32 แล้วจึงส่งต่อไปยังเว็บ โดยไม่ทำให้ลูปอ่านเซนเซอร์ค้าง

ในส่วนซอฟต์แวร์ยังต้องจัดการการเชื่อมต่อที่อาจหลุด การส่งข้อมูลแบบสด การบันทึกเฉพาะช่วงที่ทำเซต และการเก็บข้อมูลให้ผูกกับผู้ใช้และเซสชันได้ถูกต้อง

## 1.3 อุปกรณ์ทั้งหมดที่ใช้ในงาน

### Hardware

- Arduino Uno หรือ Nano — อ่าน sEMG และ FSR ด้วย ADC แล้วส่งข้อมูลให้ ESP32
- ESP32 DevKit — รวมข้อมูลจาก Uno กับเซนเซอร์ I2C แล้วส่งต่อให้เว็บผ่าน Wi-Fi
- เซนเซอร์ sEMG และ FSR — ต่อเข้าขา A0/A1 ของ Uno
- MPU6050/MPU6500 (IMU) — วัดการเคลื่อนไหวและใช้คำนวณความเร็วการยก
- MAX30102 — อ่านชีพจรและใช้คำนวณค่า SpO2 โดยประมาณ
- MLX90614 — วัดอุณหภูมิผิวแบบไม่สัมผัส
- LCD 16x2 พร้อม I2C backpack, active buzzer และปุ่มกด 2 ปุ่ม — แสดงผลและควบคุมอุปกรณ์
- ตัวต้านทานสำหรับ pull-up บัส I2C และ voltage divider ระหว่าง Uno TX (5V) กับ ESP32 RX (3.3V)

รายการอุปกรณ์แบบเต็มพร้อมจำนวนและจุดต่ออยู่ในหัวข้อ 3.1

### Software

- Arduino framework (C/C++) — เฟิร์มแวร์ของ Uno และ ESP32
- Python, FastAPI, Pydantic, Motor — backend และการเข้าถึง MongoDB
- TypeScript, SvelteKit — frontend และแดชบอร์ด
- MongoDB — ฐานข้อมูล
- Docker, Poetry, npm — สภาพแวดล้อมพัฒนาและรันบริการ

### Library

- `Adafruit_MLX90614` — อ่านค่าอุณหภูมิจาก MLX90614
- MAX30105/heart-rate library — คำนวณ HR และ SpO2 จาก MAX30102
- `LiquidCrystal_I2C` — ควบคุมจอ LCD ผ่าน I2C backpack
- MediaPipe และ OpenCV.js — วิเคราะห์ท่าทางและนับจำนวนครั้งจากภาพกล้องในเว็บ
